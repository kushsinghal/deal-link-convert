# RCA — DealLoot deploy failed at build_image (run cd4f768a-3ce6-428e-bce6-0f4d4f722731)

## Symptom
`build_image` failed in the `frontend-build` stage (step #21, `frontend-build 12/13`):

```
$ cd .. && yarn install --frozen-lockfile && node scripts/build-production.mjs
info No lockfile found.
Error: Cannot find module '/scripts/build-production.mjs'
  code: 'MODULE_NOT_FOUND'
```

## Immediate cause (proven)
The build used the **stock FARM template** (confirmed: no manifest override exists in GCS).
Its frontend-build stage does `COPY frontend/ /app/` with `WORKDIR /app`, i.e. it copies **only the contents of `frontend/`** into the build image, then runs `yarn install && yarn build` there.

`frontend/package.json` is a shim:
```json
{ "name": "dealloot-preview",
  "scripts": { "build": "cd .. && yarn install --frozen-lockfile && node scripts/build-production.mjs" } }
```
Because only `frontend/` was copied, `/app` is the shim's root; `cd ..` lands at `/` (image filesystem root), and `scripts/build-production.mjs` (which lives at the **repo root**, never copied) resolves to `/scripts/build-production.mjs` → `MODULE_NOT_FOUND`. That is the exact failure.

## Underlying cause (architecture mismatch — the real problem)
The repo is NOT a FARM app. The real app is at the **repo root** `/app`: a **TanStack Start + Nitro SSR Node server** (`package.json name: tanstack_start_ts`).
- Build: `scripts/build-production.mjs` runs `vite build` with `NITRO_PRESET=node-server` → emits a Node server at `.output/server/index.mjs` (NOT static `build/`/`dist/`).
- Run: `scripts/start-production.mjs` imports `.output/server/index.mjs` and listens on **port 3000** (requires `MONGO_URL`, `DB_NAME`, `ADMIN_PASSWORD`≥16, `SESSION_SECRET`≥32).
- `backend/server.py` is a thin **FastAPI reverse proxy** that forwards `/api/*` to the Node server via `NODE_INTERNAL_URL` (`http://127.0.0.1:3000`).
- `render.yaml` confirms the intended target: a single **Render** Node web service (`buildCommand: ... node scripts/build-production.mjs`, `startCommand: node scripts/start-production.mjs`, `healthCheckPath: /api/public/stats`).
- `frontend/package.json` is only a shim to coerce the FARM frontend-build stage into building the root app.

Even if the root source were copied so the build succeeds, the FARM template still cannot run this app:
1. **No static frontend to serve.** `build-production.mjs` produces a Nitro **Node server** (`.output/`), not `build/`/`dist/`. The FARM final image serves static files from `/usr/share/nginx/html` via nginx — there is nothing for it to serve.
2. **No Node runtime in production.** The final image is `FROM ${BACKEND_IMAGE}` (Python backend base). Node exists only in the frontend-build base. The stock `entrypoint.sh` launches FastAPI + nginx only — nothing ever starts the `:3000` Node SSR server, so the FastAPI proxy (`NODE_INTERNAL_URL=127.0.0.1:3000`) would return 503 at runtime.
3. **frontend_type = cloudflare** (set on this run) expects the frontend as static assets uploaded to R2 and served by a Cloudflare worker that proxies `/api` to the k8s backend. An SSR app that renders HTML at `/` has no such static bundle — the page routes would 404 at the worker.

These are architectural/base-image/run-config constraints, not knobs in the 6 manifest files, so a manifest override cannot make this app run as-is.

## Recommended fix (E1 / main agent — source restructure)
Pick one:
- **Option A — Conform to the FARM template (recommended for Emergent).** Restructure into a genuine static React/Vite frontend under `frontend/` (building to `build/`/`dist/`) + the FastAPI backend under `backend/` serving the real `/api` routes (not a proxy to a Node server). Drop the TanStack SSR/Nitro Node-server runtime and the `frontend/` shim. Then redeploy.
- **Option B — Deploy where the architecture fits.** This app is already Render-ready (`render.yaml`): a single Node SSR web service. Deploy it there instead of the Emergent FARM pipeline.

Note: Option A is a substantial rewrite (the app currently relies on TanStack Start server routes for `/api/*`, e.g. `/api/public/stats`). Confirm the data/feature set can be reproduced on FastAPI before committing.

## Secondary note
Requested subdomain `dealloot` was not applied — the deployment name is `try-it-now-80` (URL `https://try-it-now-80.emergent.host`). The subdomain is moot until the build model is resolved; revisit after choosing a fix path.

## Not the cause (ruled out)
- Not a missing dependency / lockfile issue (the "No lockfile found" line is a side effect of the shim running in the wrong dir).
- Not a secrets issue — build failed before runtime; secrets never evaluated.
- Not a transient/infra failure (deterministic `MODULE_NOT_FOUND`).
